# MotionBench Windows 桌面版

桌面版将同一套运动表现工作台放入独立应用窗口，通过 Windows 的 `.exe` 或快捷方式启动。用户无需双击 HTML、手动运行本地服务器或安装 Python、Node.js；桌面包自带运行所需的 Chromium 和 Node 运行时，计算与报告仍使用仓库中的原有模块。

桌面版本为 **2.19.0-desktop.1**，基于网页版 [v2.19.0](https://github.com/ZekeNiu/MotionBench/tree/v2.19.0)，精确源代码基线为 `e9e10bbdcf3bfbe8e4a86c31b446e1c18feb2cab`。桌面开发分支为 [desktop-windows-2.19.0-20261011](https://github.com/ZekeNiu/MotionBench/tree/desktop-windows-2.19.0-20261011)。原网页版、`main`、已有版本标签及已有发布包保留。**代码回退与运动员数据恢复是两件独立的事。**

本轮锁定 Electron **44.7.0**、electron-builder **26.15.3**，通过 [Windows 构建工作流](../.github/workflows/desktop-windows.yml)生成 x64 安装包与便携版。版本与安装包身份以构建产生的 `build-provenance.json` 和 `SHA256SUMS.txt` 为准。

## 安装与首次运行

本轮发行目标为 **Windows 10 / 11，x64**。Windows ARM64、32 位、Windows 7 / 8 / 8.1 和 macOS 不属于本轮安装验收范围。下载时选择本轮桌面发行说明指向的安装包或便携版，并对照 `SHA256SUMS.txt` 核验，避免拿到旧版 HTML 试用 ZIP。

成功的 [GitHub Actions 构建](https://github.com/ZekeNiu/MotionBench/actions/workflows/desktop-windows.yml)会提供 `MotionBench-Windows-x64-运行编号` 下载附件。解压后包含：

- `MotionBench-2.19.0-desktop.1-Setup-x64.exe`：每用户安装包。
- `MotionBench-2.19.0-desktop.1-Portable-x64.exe`：便携版。
- `SHA256SUMS.txt` 与 `build-provenance.json`：校验值、提交和构建来源。

只有通过测试的工作流才上传该下载附件；失败运行的测试证据不是可用安装包。Actions 附件有保留期限，本轮配置为 90 天；长期可回退的源代码与标签另外保留。若之后创建 Release，以明确的发行链接为准。

| 发行形式 | 使用方式 | 用户资料位置 |
| --- | --- | --- |
| 每用户 NSIS 安装包 | 运行安装程序，从开始菜单或快捷方式启动 | 当前 Windows 用户的固定应用资料目录 |
| x64 便携版 | 直接运行 `.exe`，无需安装工作台依赖 | 与安装版相同；不写在 `.exe` 旁边 |

安装版和便携版在**同一个 Windows 用户**下共用桌面资料库。更换 `.exe` 的存放位置不会改变资料位置；把便携版复制到另一台电脑或另一个 Windows 用户，不会随程序复制测试资料或 AI 密钥。需要携带资料时，另行导出完整备份。

首次启动没有原浏览器资料，会显示工作台的示例记录。已有桌面资料不会因更新应用而重新生成示例。桌面版限制为一个应用实例、一个工作台窗口；再次启动会返回现有窗口，避免同时向同一桌面资料库写入。

本轮安装包尚未配置代码签名，Windows 可能显示“未知发布者”或信誉提示。发布包的身份应以本仓库、明确版本和校验值核对；本项目不要求关闭防病毒或浏览器安全保护。是否能在用户真实环境安装、启动和升级，需要在 Windows 机器上实际确认。

## 从旧 HTML 或本机启动器迁入资料

浏览器的 IndexedDB 按浏览器、来源和页面路径分隔；桌面版使用独立来源和资料目录。安装程序无法自动读取原浏览器资料，也不会扫描 `D:\OneDrive\工作\言鼎\测试工作台` 或复制浏览器 profile。

1. 在**原文件路径、原浏览器、原入口**打开旧版，等待当前录入保存完成。
2. 打开“备份与恢复”，选择“导出完整备份”，保存 `.motionbench.jsonl`。先保留这一份迁移前备份，原 HTML 与原浏览器资料继续保留。
3. 打开桌面版的“备份与恢复”，选择导入方式并打开该文件。“恢复为完整资料库”以导入库替换当前活动库；“合并到当前资料库”保留当前内容并采用已有冲突处理规则。
4. 核对运动员、测试记录、日期、队伍、测试方案、评价方案、归档与回收站；抽查有原始试次的 FVP / 冲刺 FVP、图表选项和报告正文。
5. 关闭并重新打开桌面版，确认资料仍在；再从桌面版导出一份完整备份，另存为迁移后的检查副本。

完整 JSONL 保留整个资料库；“本次测试 HTML / JSON”和报告 PDF 都不能替代完整库备份。旧 JSON 和保存过的 HTML 继续使用原有导入兼容链路，但其能携带的内容以该旧格式为限。备份校验或关联检查失败时，导入不会将暂存库设为活动库。

桌面版与原网页版**不会自动同步**。同时维护两个版本时，请明确当前以哪一份资料为准，使用完整备份交换。不要把同名运动员当成同一个 ID，也不要在两个版本之间反复导入未经核对的旧副本。

## 数据保留、退出与日常备份

默认应用资料目录为：

```text
%APPDATA%\MotionBench Desktop
```

它与程序安装目录、源代码目录、HTML 所在路径分别独立。桌面窗口固定使用 `motionbench://app/MotionBench.html`；更新、重新安装或移动程序，不通过版本号改变来源、数据库名称或资料目录。测试资料继续使用 IndexedDB 的事务、分代导入和恢复机制，本轮没有更换为 SQLite。

应用版本与文件格式版本分别管理，桌面包装不重写这些结构：

| 格式 | 当前版本标识 |
| --- | --- |
| 完整 JSONL 备份 | `format: motionbench-backup`、`schema: 3` |
| 资料库配置 | `schema: 3` |
| 单次测试记录 | `schema: 2` |
| 2.19 评价方案 | `formatVersion: 2` |
| 新 Excel 模板 | `schema: 3`，继续接受旧模板 |

2.19 统一测量和评价规则的迁移及其原始副本机制仍沿用 [2.19.0 使用与回退说明](motionbench-2.19.0.md)。固定 URL、IndexedDB 内部数据库版本和上述格式版本不能混为同一个数字。

录入的有效测量按照工作台原有规则自动保存。关闭窗口前，桌面宿主要求工作台完成当前编辑、保存队列及数据库事务；保存失败或导入仍在进行时，应留在工作台处理。未提交的管理配置与正在生成的导出文件需要独立检查，不能把“等待数据库事务”理解为自动保存一切对话框草稿。

桌面版将临时录入和未通过校验的字段草稿保留到本机，支持重新打开时恢复；字段草稿不等于已保存测量，更不会以无效值写入测试记录。重新打开后仍应核对标红字段。突然断电、强制结束进程和磁盘故障不受正常关闭流程保证，应使用独立备份保护已完成的工作。

建议每次重要测试批次完成后导出完整 JSONL，并在更新应用前再保存一份。备份可放在用户指定的目录或同步盘；运行中的应用资料目录保持默认位置。本轮没有将实时数据库移到 OneDrive，也没有提供实时数据库同步或自动备份。

卸载与更新策略保留用户数据；主动清空 `%APPDATA%\MotionBench Desktop` 会删除桌面资料。手工复制资料目录只应在程序完全退出时作为额外副本，跨版本、跨电脑迁移仍以经过导入验证的完整 JSONL 为主。

## 回退与两种版本共存

| 情形 | 操作 |
| --- | --- |
| 返回原网页版 | 保留原 HTML、原浏览器入口和迁移前备份；使用 GitHub 的明确网页版标签取回原程序 |
| 桌面版产生的新资料需要回到网页版 | 先从桌面版导出完整 JSONL，在支持同一数据格式的网页版导入并核对；迁移前备份不包含这些新资料 |
| 更换桌面程序版本 | 先导出完整备份，再更换程序；若新版本改变数据 schema，依照该版的兼容和回退说明恢复 |
| 撤销上一次完整导入 | 使用“恢复上次资料库”，它切换保留的活动代；它不是所有历史修改的无限撤销 |
| 返回不能读取新格式的旧程序 | 使用该旧程序支持的升级前备份；先另行保留新版新增资料，不静默丢弃新字段 |

Git 的分支、标签和源码提交保护代码，完整 JSONL 保护测试资料。回退 Git 提交、替换 HTML 或安装旧 `.exe` 不会自动还原资料库。网页版与桌面版有独立资料目录，原浏览器数据不会被桌面安装或卸载修改。

## AI 设置与隐私

离线录入、计算、图表、Excel 和报告 PDF 不依赖 AI 网络服务。启用 AI 时，在桌面版“AI 服务”里填写 HTTPS API 基础地址、密钥和模型并保存。读取模型列表后，选择模型还需要保存设置。

桌面版通过 Electron `safeStorage` 在 Windows 下使用当前用户的 DPAPI 加密凭据。原 Python 启动器的凭据与桌面凭据分别保存，不自动复制或覆盖；初次使用桌面 AI 时需要重新输入密钥。换电脑、换 Windows 用户或重装系统后，应重新配置。完整 JSONL、报告和源代码都不包含 AI 凭据，备份资料不会备份密钥。

明文密钥不读回页面，只向用户配置的服务发送认证请求。更换服务地址时需要提供该服务的密钥；凭据保存使用修订检查，旧配置不能悄悄覆盖新设置。宿主仅转发模型列表和聊天接口，拒绝携带凭据跟随外部重定向，并限定返回格式、大小和等待时间。

AI 请求沿用工作台的当前测试及训练背景范围，不发送其他运动员资料。自由备注可能包含用户自行填写的身份信息；请求前请核对内容。导出备份、PDF、HTML 和 Excel 本身可能包含运动员信息，应作为业务文件保管。应用没有自动将测试资料上传 GitHub，也没有设置自动遥测或自动更新通道。

## 桌面架构与保留的功能

| 层 | 职责 |
| --- | --- |
| 原 `src/` 模型和 UI | 保持运动员、测试、稳定 ID、单位、代表试次、图表及评价行为；网页和桌面共用 |
| 原 PDF / Excel 模块 | 保持现有字段、报告模型、图表及导入校验；下载由桌面窗口与 Windows 文件对话框处理 |
| 桌面主进程 | 管理原生窗口、单实例、文件保存、固定资料目录、受限 AI 转发和关闭流程 |
| 受限宿主入口与能力标记 | 通过固定自定义来源处理所需 API，页面不获得任意文件、命令或 Node API |
| 固定的自定义来源 | 从应用内资源加载本地工作台，接收受限 API；不启动 HTTP 监听端口 |

内置图表、人体图及依赖随应用分发，离线启动不访问 CDN。模型没有在桌面主进程重新实现，避免网页版、桌面和报告使用不同公式。文献链接在外部浏览器打开，工作台窗口不导航到外部网页。渲染器保持沙箱、上下文隔离及 Web 安全，不通过禁用跨域保护解决 AI 连接。

便携版仍是独立 Windows 软件，内部使用 Web UI 不要求用户管理 HTML。应用本轮不提供自动更新、安装签名证书、云端多人协作或 SQLite 后端；这些能力如后续增加，应独立设计程序版本、资料兼容和升级恢复。

## 验证边界与已知问题

本轮测试结果以仓库中实际执行的验收记录为准。提交了构建流程、成功生成安装包或在合成资料上运行测试，都不等于已在用户真实 Windows 环境完成安装、迁移、打印、升级和卸载验收。

发布前及用户首次采用时，应确认：普通用户安装和便携启动、退出立即重开、中文及长文件路径、真实 PDF / Excel 保存、导入失败保留旧库、重装与卸载数据保留，以及 API 密钥在当前 Windows 用户下的加密可用性。真实运动员资料不作为 Git 测试夹具或 CI 数据上传。

2.19.0 已在导入激活时核对活动代及写入修订，并保留升级前资料；这是原网页版的存储改动，不归功于桌面包装。完整备份仍通过多个读取事务遍历各表，旧 Repository 实例的“恢复上次资料库”仍有代指针边界，不将前版所有并发缺陷宣称修复。桌面单窗口与单实例限制正常使用中的写入来源。前版复现与背景见 [2.17.2 已知问题](local-fixes-2.17.2.md)，当前实现以 `src/ringside-store.js` 为准。本轮没有扩大计算功能，也没有把尚未完成的原生 Excel 或用户设备验收列为通过。

## 常见问题

**安装后为什么没有原来的运动员？** 原浏览器和桌面资料库独立；按迁移步骤导出并导入完整 JSONL。

**便携版为什么没有把数据存到 USB 盘？** 它与安装版使用当前用户的固定资料目录。跨电脑携带数据需要完整备份，密钥另行配置。

**可以同时用桌面和网页版吗？** 可以，两个来源独立保存；它们不会同步，交换资料需要明确导入并核对。

**程序包更新会清掉资料吗？** 程序资源与资料目录分离；仍应在更新前备份，尤其是以后涉及数据格式升级的版本。

**网页版本还能继续使用吗？** 保留原网页版标签和成品，原 `src/` 构建路径仍可产出独立 HTML。

**关闭窗口时提示未保存怎么办？** 返回相应录入、管理配置或 AI 设置，完成保存或明确放弃未提交的配置；数据库保存失败时先处理并备份，不能以强制退出代替保存成功。

**开发者如何复现构建？** 在桌面分支使用 Node.js 24 与 Python 3.12，执行：

```powershell
npm ci
npm run build
npm test
npm run test:desktop-unit
npm run dist:windows
npm run verify:desktop-package
$env:MOTIONBENCH_EXECUTABLE = "$PWD\dist-desktop\win-unpacked\MotionBench.exe"
npm run test:desktop
```

Windows 发行包在 `dist-desktop`；测试使用隔离的合成用户目录，不操作用户真实浏览器资料。用户运行发行包无需安装开发工具。
