# MotionBench 交付约定

用户于 2026-10-19 明确要求：每次优化完成后，同步更新安装包、当前安装版及 GitHub。该约定持续适用于本项目，无需每轮再次确认；用户另行限定只调查、只做候选或暂停发布时，以当次要求为准。

交付必须包含：

1. 从 `src/` 修改并重建单文件 HTML；对最终文件进行适当验收，记录准确的版本和校验值。
2. 正常关闭现有程序，核验并备份真实用户资料及旧安装目录；保留可回退副本。
3. 生成 Windows 安装包和便携版；核对包内文件，使用资料副本验收后再更新原安装目录。
4. 核对原始测量、记录、评价方案、人工解读、日期和图表选择的保留情况，验证正常保存、关闭、重开及普通快捷方式。
5. 同步 GitHub 源码、版本标签、正式 Release 和附件；核对远端提交与附件校验值。公开演示站点沿用现有自动发布流程。
6. 如实报告交付结果及尚未完成的项目；本地候选、自动验收和用户验收分别记录。

正式附件使用明确的允许清单，不包含真实资料、私密验收快照或凭据。

验收注入的写入保护器只在验收作用域内有效。当前 `tests/desktop-system-v2248.cjs` 及新入口通过 `tests/helpers/display-guard-lifecycle.cjs` 管理既有保护器，正常结束、断言失败或部分安装失败均须恢复原方法；旧保护器与历史凭据保持原字节。失败现场先保存恢复资料和保护日志，再清理注入，不能把带有测试拦截的窗口留给用户继续操作。交付时以普通快捷方式重新打开干净窗口。

图表选项与日期交互优先在隔离资料副本中验证。真实资料核验必须保护原记录和正文；用户在可见窗口的试点操作不应被误判为产品控件故障。若运行期选择发生变化，应保全选择并按实际授权处理，不能将已失败的验收记录改为通过。

仅修改验收工具时，同步工具源码并运行针对性检查，保持已核验的应用版本和正式附件。历史回执绑定当时的运行器；运行器变化后须使用新的回执，不能修改旧校验值让其匹配当前工具。本次2.24.8回退的独立证据和运行器保存在 `output/rollback-2.24.8-20261020/`，控件恢复证据保存在 `output/controls-recovery-2.24.8/`。

验收按[变更风险策略](verification-strategy.md)选择范围：显示层优化运行受影响组件及实际导出检查，计算、存储、PDF引擎或运行环境变更扩大回归。未改部分可在逐文件确认后继承完整基线，须明确与本轮重新执行的检查区分。资料保护及最终包、安装、远端附件核对始终执行。
