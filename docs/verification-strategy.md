# MotionBench 按变更风险验收

适用于每次优化后的本地验收与发布。验收范围由最终源码差异及受影响行为决定，不把全量回归作为每次界面调整的固定前提。真实资料保护、最终安装包身份和发布附件校验始终保留。

## 本轮范围：2.24.8

本轮调整纵向报告的评价显示、疼痛优先级、结果同行布局及趋势图评价底色。允许调整的业务源码为 `src/ringside-result-display.js`、`src/ringside-longitudinal.js`（仅向显示投影提供评价规则）、`src/ringside-longitudinal-view.js` 和 `src/ringside-longitudinal.css`。版本标识、生成文件、针对性测试与交付脚本单独列明。

测量、代表值、评分阈值、双侧差异公式、存储、迁移、单报告算法及 Electron 权限边界不在本轮修改范围。出现这些部分的差异时，不得沿用下列精简范围，应先重新评估影响。

## 可复用的完整基线

2.24.7 的完整验收记录位于 `docs/acceptance-2.24.7.json`，基线提交为 `77e97a5`，正式标签为 `v2.24.7-desktop.1`。复用前记录其完整提交号、验收文件校验值及测试记录的实际存在性。

基线说明未改动部分已在该版本通过验收，不能冒充 2.24.8 的运行结果。新记录必须分别列出：

- 本轮重新运行的测试、运行器校验值、最终 HTML 与相关源码校验值。
- 从基线继承的验证范围，以及支持继承的逐文件字节一致性证明。
- 未运行的设备、服务及其他检查；用户验收仍单独记录。

字节一致性至少覆盖未列入变更清单的全部 `src/` 文件、`desktop/`、`vendor/`、构建脚本及资料保护辅助文件。依赖配置除版本号外的内容也须一致。只比较某一个模型文件不足以证明其他流程未受影响。

## 本轮本地检查

### 1. 相关单元检查

逐套执行，保存各套退出状态、检查数量和日志。本轮选择以下八套相关检查，另外增加一套本次行为用例，不运行 64 套总入口：

| 测试 | 覆盖原因 |
| --- | --- |
| `comparison-trend-tests.cjs` | 评价显示投影、趋势阈值、底色、缺失和不兼容规则 |
| `longitudinal-model-tests.cjs` | 原数值、评价规则来源、疼痛标记和比较结果保留 |
| `longitudinal-view-tests.cjs` | 数值与标签布局、投影和报告重建 |
| `longitudinal-display-state-tests.cjs` | 本轮新增显示字段不污染图表选择和独立正文 |
| `longitudinal-store-model-tests.cjs` | 纵向显示数据不写入原始记录或改变保存约定 |
| `evaluation-v220-model-tests.cjs` | 统一标签不改变评价方案的原始名称、阈值或适用性 |
| `isometric-reference-model-tests.cjs` | 力量、双侧差异、关节平衡及疼痛的原有计算语义 |
| `v2244-display-preservation-tests.cjs` | 原始记录、人工正文、日期和图表选择的保护断言 |
| `comparison-assessment-v2248-tests.cjs` | 本轮统一文案、疼痛优先、分期标准底色及打印投影 |
| `comparison-assessment-v2248-tests.cjs` | 本次统一标签、疼痛优先级、评价底色及其边界 |

新增断言必须覆盖实际风险：三个统一标签的映射、灰色自定义评价处理、疼痛覆盖绿色结果、双侧差异例外，以及不同日期使用不同或不兼容评价规则时底色的边界。不得只断言实现内部细节。

### 2. 一组浏览器与实际 PDF，加交互检查

运行 `comparison-assessment-v2248-browser-tests.cjs`，使用独立合成资料，覆盖：

- 各项目数值后同行标签，双侧差异保留自己的表达。
- 红、黄、绿标签统一，疼痛为红，且不篡改数值或原始标记。
- 有评价规则时绘制正确底色；关闭、缺失或不兼容规则时不误画底色。
- 两点、多点、缺测、负值、长单位及 SFV 使用相同图框。
- 桌面、390 像素窄屏及打印布局中的可读性和对齐。
- 实际导出一个不超过五页的聚焦 PDF，检查评价、底色、日期、行和图的保留；渲染并检查其全部页面，无需再次生成全项目长报告。

另运行 `comparison-polish-browser-tests.cjs --skip-pdf`，核对上一轮图框、对齐及空平衡段行为；它不重复生成旧的长篇PDF。再运行 `comparison-trend-interaction-tests.cjs`，检查鼠标、键盘与触屏提示。只有共享交互代码或浏览器差异存在新的风险时，才增加其他浏览器及交互套件。

### 3. 已打包程序的最小流程

使用最终包和独立合成资料运行 `longitudinal-browser-tests.cjs --desktop`，不加 `--pdf`。它覆盖实际程序初始化、三期选择、原始资料保留、代表值切换、正文保存、JSON/HTML、单报告回退及正常关闭重开。本轮不重复生成完整原生长 PDF，也不重跑与本次变更无关的 AI 加密、Excel 和安装更新协议检查。

### 4. 每次发布保留的资料和交付保护

正常关闭真实程序，通过 Explorer 环境确认实际安装目录和资料目录，完成逐文件校验的物理备份，保留旧程序与回退信息。

依次验证旧版资料副本、候选包、更新后的原安装目录及重开；核对原始记录、评价方案、人工正文、日期与图表选择。普通快捷方式应无测试参数启动，且指向新版本。

最终 HTML、包内 HTML、ASAR、安装包、便携版及验收文件必须校验一致；重新构建应可复现。发布继续使用十个附件的明确允许清单，核对 GitHub 提交、标签、Release、附件数量和校验值，真实资料不得进入附件。

## 何时扩大或全量回归

| 变更或证据 | 增加的检查 |
| --- | --- |
| 数值、评分、公式、代表值、方向或单位变更 | 对应模型全部边界用例；跨项目共享计算变更时运行全部模型套件 |
| 存储、迁移、导入或资料结构变更 | 迁移、旧资料、多版本往返、保存失败与重开完整回归 |
| PDF 分页、导出器或通用图表机制变更 | 完整长报告、跨页表格、不同日期数量及原生下载检查 |
| Electron、依赖、安全边界、自动更新或打包方式变更 | 桌面模块、安全及原生 smoke，并验证安装或更新流程 |
| 未解释的跨项目失败、差异超出白名单或基线缺失 | 停止复用相关基线，定位原因并扩大到受影响范围 |
| CI 或正式发布的周期完整回归 | 在后台运行全量套件，单独报告结果；其通过与否不能覆盖本地已知失败 |

精简验收不是减少对本轮行为的覆盖，而是避免把未变化流程的重复执行当作本轮正确性的主要依据。每轮记录必须能回答：改了哪些输入、哪些风险重新验证、哪些旧证据仅因字节一致而继承。

## 本轮可执行入口

`scripts/release_v2248.py` 提供单一交付入口。`run units`、`run browser`、`run interaction` 和 `run native` 生成本轮针对性证据；`verify --require-candidate` 保护实际安装前的条件；`verify --require-private --record` 写入完整本地交付记录；`package` 只整理已提交、已验证的十个公开附件。

`prepare`、`install` 和 `shortcut` 使用已提交的 2.24.7 动作模板，确定性生成适配器，再通过真实 Explorer 环境执行。模板及生成文件均校验身份，旧脚本和旧版本验收约定保持不变。`bind-checkpoint` 在核实物理备份全部字节后固定本次备份校验值；未固定或不一致时，后续安装与私资料门禁拒绝继续。

后台 Windows CI 仍执行全量模型、桌面模块、浏览器、原生长 PDF 和通用 smoke，并额外执行本轮针对性用例。其完成状态单独报告，不作为界面小改每次本地重复执行全量的理由，也不能替代已经发现的失败。
