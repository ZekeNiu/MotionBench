# MotionBench 2.7.0

本版将产品从 Ringside 更名为 MotionBench，覆盖跨项目的运动表现评估。更新界面标志、图标、页面标题、报告页眉、PDF 作者信息和下载名称。保留旧 HTML 文件名作为兼容入口，内部模块名和数据结构不迁移。

## AI 使用流程

“生成离线摘要”按原有本地规则生成手写起点。“生成 AI 综合建议”把当前有效测试、专项和训练背景交给所选模型，要求综合判断、解释相互支持或矛盾的证据，并给出动作选择、负荷、组次、休息、周安排、进阶和复测条件。正文以实际训练问题组织，不按每个指标机械套模板。根据后续确认，自动生成正文最多两页 A4：通常900–1400个汉字、2–3个训练重点，保留可执行剂量。只说明会改变本次动作或负荷的具体条件，删除泛泛免责声明与重复背景。使用与真实 PDF 共用的分页器预检，超长时请同一模型再精简一次，仍超长则明确提示而不截断正文。PDF 中建议另起一页以保持最多两页的连续阅读。

生成期间有持续计时、按钮状态和取消等待入口；最多等待 300 秒。错误保留在页面，区分地址、密钥权限、额度、非 JSON、空正文、截断和网络访问问题。新建议先进入可编辑预览，应用后更新正文并保留上一版。数据改变或切换记录后不使用过时结果。

等长方向已设置正目标时，发给 AI 的资料明确标记该评价已启用，与本地报告保持一致。代表成绩、原始试次统计和推算来源分别说明，计算公式未改变。

## 中转服务的实测原因与处理

2026-10-07，对指定中转服务的独立诊断得到：

- `https://api.apikey.fan/v1/models` 带密钥请求返回 HTTP 200，列出 8 个模型。
- 最小聊天请求通过 `gpt-6.1-sol` 返回 HTTP 200。
- 浏览器对模型和聊天路径发出的 `OPTIONS` 预检均返回 HTTP 403。即使响应包含允许跨域的头，失败的预检状态仍阻止浏览器继续调用。
- 独立 Chrome 从 `file://` 发起的真实调用重现了预检失败。

因此提供 `Start_MotionBench.cmd` 本机入口：Python 标准库服务仅监听 `127.0.0.1`，同源页面通过它连接配置的 HTTPS AI 接口。使用 Origin、Host 与随机令牌校验，只支持模型列表和聊天路径，不随重定向发送凭据。公网上的服务域名允许经用户 VPN 的 DNS 解析；不把 VPN 的模拟地址误判为服务本身无效。

直接打开单文件 HTML 的模式仍可使用支持浏览器直连的服务。中转服务本身的预检配置没有被修改；本机入口是在产品中交付并实测的访问方式。

## 数据与密钥

API Key 只在页面及当前请求的内存中使用，不写入磁盘 HTML、浏览器持久存储或备份。刷新后清除。填写表单不会生成 Git 提交，也没有自动推送流程。导出 HTML 删除本机连接令牌。公开发布不包含本地运动员库、输入密钥、私人备份或过程输出。

原文件路径继续访问其已有浏览器记录。改用新文件名、本机入口或另一浏览器前，需从原页面导出运动员库，再导入新入口；不能跨浏览器存储源自动读取原记录。

## 验证范围

验收包括模型计算回归、AI 状态/错误/取消/重试/预览应用、五种窗口宽度、旧路径历史保留、实际备份与 HTML 导出后重开、本机服务边界、真实中转模型和实际 PDF 下载逐页查看。具体成品哈希、数量与结果记录在 [验收摘要](acceptance-2.7.0.json)。

真实 AI 场景使用独立浏览器和模拟数据：完整拳击数据、仅自重且每周一次的篮球、关闭评价标准的中长跑、缺少训练背景，以及膝痛与部分缺测。生成成功与建议质量分别检查。早期完整报告曾超过原 175/180 秒等待期限，本版增加等待时间且保留明确失败反馈。

交付流程置信度高；模型建议质量为中等置信度，基于上述有限场景的人工核对，不代表任意模型、运动员或伤病情况均能得到可靠建议。没有验证物理手机、纸张打印及全部第三方 AI 服务。
