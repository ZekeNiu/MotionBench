# MotionBench 2.24.11 定向验收与交付范围

本轮基于 `4ff10c5782a8008aac1d12c1ea411415f99ef788`（2.24.10），处理个人报告的五项展示要求。2.24.9 保持撤下，不恢复其雷达图分档背景。本文件定义检查与交付条件，实际结果、PDF 页数和文件身份以本轮最终收据为准。

## 根因与历史边界

历史审计已对照 2.16.1、2.20.1、2.22.0、2.24.8 与 2.24.10：FMS 专用文字映射、药球独立比较卡片、个人“未分级”标记和 FVP 方法说明在旧基线中均已存在，不能归因为 2.24.10 新增。2.20 确实统一过能力标题的字体、颜色、宽度和内部标题层级；该修复仍在，但独立能力区域与其他主要章节的容器层级仍不一致。对于没有提交到当前历史的本机修改，证据不足，保留未知。

旧个人报告测试曾明确允许“未分级”灰色标记；旧标题检查比较的是素质标题样式，没有覆盖主要章节结构。这些检查通过不代表当前用户要求已经满足。本轮按实际评价依据、图表尺寸和章节结构补齐契约，不把旧快照或通过数量当作正确性的替代。2.22 删除的“查看能力评分的计算”与本轮指定的 FVP“测试条件、计算与来源”属于不同说明。

本轮交互复验另确认一个通用个人章节状态缺陷：两处既有主章节及新增能力主章节的折叠状态已有缓存写入，但启动路径没有读取恢复；按记录划分的界面状态也未完整写入缓存。修复范围为界面缓存的保存与启动恢复，以记录 ID 隔离个人报告状态，并与纵向比较状态区分，不修改业务资料 schema。此缺陷与旧评价文字、图表尺寸及方法说明的历史原因分别记录，不能混为同一次内容回退。

## 行为与风险

- FMS 评价统一为“预警／关注／优秀”，沿用既有评分与红绿灯状态。缺失动作不生成灰色评价；七个动作、原始单项或左右侧得分、疼痛记录及备注完整保留。“未完成动作”原本是录入 1 分后的旧文字映射，不是新增的自动动作识别。
- 药球反手投掷的比较卡片使用可复用的固有尺寸上限，分别核对单侧和双侧结果、普通桌面与窄屏。保留实测距离、单位、参考目标、统计与原始试次，不靠改变数据或纵横比例压缩内容。
- 乳酸结果仅在确有分级依据时显示评价。没有命中等级区间的“未分级”不生成灰色标记；真正命中的自定义灰色等级以及既有目标评价继续显示。以是否命中等级或具备目标评价依据判定，不能按文字黑名单或颜色统一删除。其他个人项目的既有评价展示不在本轮改动范围。
- “能力结构分析”使用与其他主要章节相同的折叠容器及标题层级，内部区分“发展方向”和“力–速度剖面与弹性”，卡片与参数继续使用对应的下级标题。修复通用个人主章节折叠缓存的启动恢复，分别检查筛查、运动表现、能力结构三个主章节、多个个人记录及个人/比较切换，不能串用折叠状态。检查刷新及局部 FVP 图表更新后结构仍完整；PDF 按已有主要章节打印规则保留内容，不能因空模型或外层折叠丢失有效能力卡片。
- 个人 FVP 移除指定的“测试条件、计算与来源”展示块，保留负荷代表点、原始试次、计算结果及底层协议和来源。纵向报告显式保留既有说明，个人展示改动不得外溢到纵向日期、参数、曲线、评价、正文或保存归属。

允许变化的业务文件列在 `scripts/release-v22411.json` 的 `changedSource`，包括界面状态缓存恢复、公共文字出口、个人渲染、比较结果尺寸、能力结构及相应 PDF/纵向调用边界。其余 `src/`、`desktop/`、`vendor/`、构建脚本和资料保护辅助文件应与基线逐文件核对；依赖与打包配置仅变更版本号。若实际改动超出配置范围，先补充对应检查，不能自动继承旧证据。原始测量、评分规则、拟合算法、评价标准、人工正文及已有比较文档不得随展示调整被改写。

## 本轮运行

`python scripts/release_v22411.py units` 执行配置内十四套定向检查，覆盖个人评价与布局、既有报告/图表模型、FVP 与双弹性框架、纵向评价和趋势、上一版控件与解读、保护器退出清理。逐套记录退出状态、运行器和相关源码身份。既有测试只更新本轮明确改变的契约；保留真正自定义灰色等级、其他项目既有行为以及纵向结果的反向案例，防止用宽泛允许列表掩盖错误。

| 证据 | 检查范围 | 完整运行预期 |
| --- | --- | --- |
| `output/implementation-2.24.11/focused/results.json` | `personal-report-v22411-browser-tests.cjs`：三份独立个人报告、五项展示、单/双侧药球、有效灰色等级及目标评价、三主章节折叠恢复与多记录隔离、FVP 局部更新、保存重开、JSON/HTML 往返、个人/比较隔离、实际 PDF 下载 | 十三项，包含实际 PDF 检查 |
| `output/implementation-2.24.11/native/results.json` | `longitudinal-browser-tests.cjs --desktop`：最终打包程序内合成资料的初始化、比较、原记录隔离、正文、保存与重开 | 十项，不重复完整长 PDF |
| `output/implementation-2.24.11/resumed/ci/full-units/unit-results.json` | 云端 `run-unit-tests.cjs` 的六十六套完整模型回归 | 后台单独记录实际结果 |

个人聚焦检查的配置门槛为 `minChecks: 13`。最小检查数仅用于拒绝不完整运行，最终收据还必须逐项包含上述十三项和实际 PDF 记录；第七项须覆盖三个主章节的折叠恢复、多个个人记录隔离、个人/比较状态隔离及 FVP 局部更新。使用 `--skip-pdf` 的运行不能计作完整个人 PDF 验收。后台 CI 另运行既有纵向控件与保存检查及完整原生/PDF 流程，不能把其未完成状态写成本地通过。

浏览器证据绑定最终 HTML、实际运行器及相关源码的 SHA256；原生证据还绑定最终 ASAR，运行前后身份一致。实际 PDF 应记录文件身份、实际页数、表格/图表完整性诊断及逐页渲染图片，并由主任务查看全部页面。DOM、打印样式或仅生成图片清单不代表完成 PDF 人工检查。本文件不预填页数或 PASS。

`python scripts/release_v22411.py rebuild` 对最终 HTML 再构建一次，检查字节一致性。本地十四套定向、个人浏览器/PDF、最终原生流程、真实资料保护和云端全量结果分别记录；本轮不在本地重复执行无关的完整模型矩阵。

## 资料保护与安装顺序

以下阶段由交付主任务串行执行，工具或文档准备不代表已经完成安装或真实资料验收。

1. `adapters`：使用固定校验值的历史模板生成本轮适配器，保留旧门禁、旧产物及旧失败回执。
2. `prepare`、`bind-checkpoint`：通过 Explorer 正常关闭程序，复制真实安装目录与真实资料目录，逐文件验证备份并固定 manifest 身份。
3. `private baseline`、`private candidate`：分别使用该 checkpoint 的两个独立资料副本，验证原始记录、正文、方案、人员、日期、显示设置和未受影响模型得到保留。
4. `verify --require-candidate`：同时核对本轮定向证据、最终包身份和两个副本阶段，满足条件后才进入安装。
5. `install`：通过 Explorer 安装；安装前再次检查 checkpoint 后真实资料未变化，安装后核对实际程序及 ASAR 身份。
6. `private installed`、`private reopened`：验证原安装目录的真实资料、正常保存/关闭和重开。失败时先保留恢复快照，再清理注入的保护器；不能把受保护器拦截的窗口交给用户。
7. `shortcut`：以普通桌面快捷方式、无测试参数启动最终可见窗口，只读核对已保存人员/日期和真实资料路径，不注入保护器。
8. `verify --require-private --record`：生成最终本地验收记录；未运行或失败的阶段不写成通过。
9. 提交最终源码与验收说明后 `package`，仅整理配置允许的十个公开附件；真实资料不进入附件。推送、Release、Demo 发布和远端附件逐项校验由主任务完成。

真实 checkpoint 使用 `D:\Application\Strength&Conditioning\MotionBench-backups\20261020-system-before-2.24.11`，不复用上一版资料快照。真实安装位置为 `D:\Application\Strength&Conditioning\MotionBench`，资料位置为 `C:\Users\ZekeNiu\AppData\Roaming\MotionBench Desktop`。以 Explorer 启动环境核对，不能用 Codex 重定向的 APPDATA 代替实际资料证据。安装前资料若发生变化，保护新状态并停止当前安装步骤，不覆盖新资料。

启动形态以实际 checkpoint 为准：若保存的是个人报告，保留原人员、记录和日期，不为满足比较断言改变用户选择；全部未打开的比较文档仍需一致，未执行的比较 DOM 断言不得计为通过。最终普通窗口不保留测试参数或保护器。合成浏览器/原生检查与真实资料保护分别证明各自范围，不能互相替代。

## 可复用工具边界

沿用 `scripts/release_delivery.py`，`scripts/release_v22411.py` 仅选择本轮范围、基线、路径与证据配置；不复制旧版业务断言充当新版本检查。资料保护适配器保留原严格证明，并通过 `display-guard-lifecycle` 在正常、失败和部分安装保护器的路径中恢复原函数；失败快照和清理结果均应保留。

验证子进程的标准 PowerShell 模块路径只作用于该进程，不修改用户系统环境。最终交付状态以实际安装、普通启动、GitHub 标签/Release 附件和 Demo 的独立收据为准；后台 CI、用户验收和未覆盖的设备/环境检查保持各自真实状态。
