# MotionBench

跨项目的运动表现评估与训练建议工作台。当前版本 **2.10.0**。录入、计算、图表、备份与 PDF 导出均可离线使用。

![MotionBench](assets/motionbench-logo.svg)

### 打开与使用

- **离线评估**：双击 `MotionBench.html`，无需安装。直接打开 HTML 时，AI 服务需要允许浏览器跨域访问。
- **使用中转 AI 服务**：Windows 双击 `Start_MotionBench.cmd`，在自动打开的页面中使用；保持启动窗口开启。需要 Python 3.10 或更新版本。其他系统运行 `python3 scripts/serve.py`。
- **更新旧版**：`Ringside_Boxing_Assessment.html` 保留为内容相同的兼容入口。把新版放回原文件位置，用原浏览器打开，可继续访问该路径的记录。切换到新文件名、另一浏览器或本机启动入口前，请先在旧页面导出运动员库（2.8.0 使用“备份与恢复”），再导入新入口；不同页面地址的浏览器数据不会自动合并。
- 下载后的两个 HTML 均可独立工作。无需使用 GitHub 网站上传测试数据。

### 迁移与回退

在原路径、原浏览器打开新版时，会先校验旧资料并写入新资料库；成功后切换，旧浏览器存储继续保留。“备份与恢复”可下载迁移前资料、导出完整备份或恢复上次导入前资料库。导入校验失败不替换现有资料。

回退到 v2.7.2 时使用迁移前备份；也可导出旧版兼容 JSON，保留已测试记录和旧版可表达的生效标准，但不包含队伍、空档案、回收站、测试方案和新增 IMTP 时点标准。分类在导出副本中转换为当时的显示名称，不保留独立分类编号及顺序快照；同名分类附编号区分。VIFT 方法文本保留，旧版不提供独立编辑入口。峰值百分比不会写成 N 标准。不要把新版完整 JSONL 直接交给旧应用。

### 两种建议有什么区别

| 入口 | 用途 | 使用方式 |
|---|---|---|
| 生成离线摘要 | 按规则整理测试发现和基础建议，作为手写解读的起点 | 无需联网或密钥 |
| 生成 AI 综合建议 | 综合指标关系、专项、训练背景和周安排，生成有剂量、取舍、进阶条件的教练建议 | 需要 AI 服务、文本模型和可用额度 |

AI 建议以最多两页 A4 为目标，生成后使用实际打印样式预检；超长时自动精简一次，保留动作剂量和关键调整条件。正文集中于本次训练需要，不加入泛泛免责声明。

点击“应用草稿”才更新正文，并保留上一版。AI 状态与已等待时间仅在解读编辑页和 AI 设置页显示，可取消等待或重试。生成期间可继续查看同一次测试，完成后返回解读页主动查看草稿；始终留在解读页且没有其他对话框时，会自动打开预览。切换运动员或测试记录会清除旧任务，未完成或过时的结果不会替换正文。

### AI 设置与密钥

在“应用设置”填写 HTTPS API 基础地址与密钥，点击“读取可用模型”，选择文本模型。不同服务的模型名称并不通用。读取模型成功后，实际生成仍可能受额度、模型权限或响应速度影响。

API Key 仅在当前页面和请求的内存中使用，不写入源码、浏览器存储、导出 HTML、运动员库备份或 PDF。刷新页面后需重新填写。浏览器输入不会修改磁盘上的 HTML，项目也没有自动 Git 提交、推送或测试数据上传功能。手动将密钥写入代码再提交则会泄漏，请勿这样保存密钥。

本机启动入口只监听 `127.0.0.1`，把当前请求转发给你配置的 HTTPS 服务；不保存密钥，不记录请求内容。AI 会收到当前测试与训练背景，不发送姓名字段或其他运动员记录；自由备注请自行去除身份信息。导出 HTML 会移除本机连接令牌，仍可独立打开。

如果模型列表可读、聊天接口可调用，但直接打开 HTML 仍报网络错误，服务可能拒绝浏览器预检。请使用本机启动入口；修改密钥或关闭浏览器安全保护不能修复服务端预检。

## 评估功能

- 固定侧栏进入数据录入、人员与测试管理；报告顶部选择运动员与记录、编辑本次数据和导出。数据录入按选人、设置测试、逐项录入、核对报告四步完成。
- 支持独立运动员与队伍管理、搜索分页、队伍筛选、批量分组或更换方案、归档和回收站。可复用测试方案保存项目顺序和推荐评价方案；历史记录保留采用时的快照。专项和惯用手分别填写。
- 共用评价方案更新后，关联的历史记录自动使用最新标准；测量条件不匹配时保留实测值。现有解读保留，并在评价依据变化时标记待复核。
- FMS、等长力量、CMJ/SJ、IMTP、负荷-速度、MAS/MSS、30-15VIFT、乳酸等测试与报告。指标库统一编辑能力分类、项目、指标及所选评价方案标准；分类改名、排序与项目调组只影响后续测试。IMTP时间点力支持同次峰值百分比评价，RFD保持N/s。
- 同条件重复试次按最佳或均值汇总；至少 3 个有效值显示均值、样本 SD 与适用时的 CV。缺测不当成零。IMTP最佳值仍跟随峰值力代表试次；百分比均值先逐次归一，实测与换算来源分开。
- 等长力量保留五轴雷达；等长力量与IMTP在桌面均为左图右表，重复统计保留在原表，手机转为上下。PDF 根据完整图表高度选择左右或上下排版，长表逐页续排。
- 等长力量评价与关节平衡采用“达标／关注／严重”短标签；未设标准的平衡比值显示灰底。悬停可查看完整原因，数值与侧别保留，常规表格与 CMJ、IMTP 对齐。
- 人体部位圆圈支持鼠标悬停、键盘聚焦和手机点击，列出当前最佳／均值模式下相关测试的侧别、实测值、评价、疼痛和缺测。绿色状态显示“优秀”，原评价和优势统计规则保持。
- 训练速度参考分别显示 MAS 和 VIFT 百分比及个人速度；30-15VIFT 测试方法独立填写。训练表列出主动／被动恢复及成对时长示例，RST 增加 5／15 秒与 5／30 秒被动恢复。
- 完整资料库使用分批处理的 `.motionbench.jsonl` 备份；继续接受旧 JSON。单报告 HTML／JSON 和离线 A4 PDF 保留导出时的评价内容。
- 数据按运动员、记录、队伍和评价方案保存在本机 IndexedDB；列表只读取摘要，打开记录时再读取测量数据。

更换专项时，请核对本次评价标准、协议和适用人群。部分内置测试与参考原用于拳击，品牌更名不会自动把这些标准变成跨项目通用常模。原始方向、单位、公式、历史记录和导入结构继续兼容。

页面与 PDF 采用统一的银灰样式，数据行白底。低矮窗口的侧栏可整体滚动，顶部关闭按钮保持可见；重新打开时会显示当前导航项。

方法说明：[速度参考](docs/speed-reference.md) · [软件结构](docs/architecture.md) · [本版说明与验收](docs/motionbench-2.10.0.md)。

## 开发与验证

需要 Python 3.10+ 与 Node.js 18+。构建使用已固定并校验哈希的本地库，不下载 CDN 依赖。

```powershell
python scripts/build.py
npm ci
npm test
npm run test:refinement
npm run test:catalog
npm run test:report-v210
npm run test:imtp-layout-v210
npm run test:management
npm run test:capacity
npm run test:management-pdf
python scripts/review_pdf.py --manifest=management-download-verification.json --output=management-render-verification.json --focused
python tests/local-server-tests.py
```

`src/` 是正式源码；修改后重新构建两个内容相同的 HTML。内部 `Ringside*` 模块名与旧文件名保留用于兼容，不代表仍以拳击作为产品定位。

可用 `node tests/live-motionbench-tests.cjs` 核对真实中转服务，密钥仅从进程环境 `RINGSIDE_AI_KEY` 读取；该测试使用独立浏览器和明确模拟的数据，会产生真实模型调用费用。默认服务为 `https://api.apikey.fan`，模型为 `gpt-6.1-sol`；先启动本机入口。它不会读取个人浏览器中的运动员记录。

`output/`、本机备份、密钥文件和验证过程文件不进入仓库。发布包仅包含干净应用、启动入口和使用说明。

## 第三方组件

离线 PDF 使用 html2canvas 与 jsPDF；来源、版本和许可证见 `vendor/versions.json` 及同目录许可证文件。
