## Product contract

- One horizontal document has focus and peers perspectives. Direct participants each select one real dated record; focus references match the focus athlete's current attributes, peers references have explicit common conditions. Allow >=2 direct participants without a reference, or >=1 with a reference.
- Local database only. References combine scope all/sport/team with sex, sport, subdivision and reusable age band. Cover all 12 user combinations through this query. Include matching subject and archived data; exclude deleted and marked sample/demo records. Current athlete profile/group determines membership. Age comes from each actual test.
- User explicitly chooses all-history/recent-12-months/custom date window on first creation; save absolute dates and selection. User defines reusable inclusive whole-year age bands. Snapshot the resolved bounds.
- Sport and a single primary subdivision are user-managed stable identities. Names and subdivision labels/types are arbitrary; never branch on their text. A subdivision belongs to one sport. Rename preserves identity; changing sport clears incompatible subdivision. Migrate only exact nonempty current sport text, keep historic record text unchanged; no aliases guessed. Same import ID + same parent retains local identity/name; different IDs do not merge merely by label; parent collision remaps incoming identity.
- Individual representative mode best/mean remains its existing complete-trial semantics. Cohort sampling is separate: latest eligible per athlete/project/compatible context; or per-metric period record selected by confirmed metric direction. Filter age/date/protocol BEFORE sampling. Latest project missing a companion metric stays missing, not filled from older tests. Derived values must already be valid within one record. Each athlete contributes once per metric.
- Mean/best retain per-metric n, source athlete/record/date, tied best sources. No zero fill. Period-record mode uses latest comparable mean for nondirectional metrics, explicitly labeled 最近测试. Ratios/model outputs are calculated per person before aggregation.
- Metric result meaning (numeric/ordinal/category) is separate from direction and ratio/CV eligibility. Extend one canonical metric direction (higher/lower/none/unconfirmed); do not add independently editable competing direction. Existing profile score directions and complete-trial selection retain historical computations. New target scoring inherits canonical direction. A centralized resolver prevents evaluation projection from changing record selection. Legacy custom auto-higher is not evidence of confirmation. Provide central review instead of per-report direction settings.
- Numeric means do not require a good/bad direction. Ordinal/category values use appropriate distribution. Built-ins declare semantics in their own definitions, custom indicators use the same mechanism. No test-name allow/deny list.
- Retain longitudinal visual family and overview/details/narrative chapters, details chart-above-table. Multiple saved references, one active on screen; independent chart visibility must not change samples. Names with dates, stable personal colors, neutral cohort symbols. Horizontal differences say higher/lower versus reference, never temporal improvement/trends. Keep scalar precision, assessments, trial SD/CV and raw trials.
- Retain individual fitted/model curves; cohort model parameters remain scalar statistics. Ability radar can show mean individual scores under the same scoring contract, using latest compatible observations. Do not recompute derived group outputs from mean input parameters or compose a fictional best individual.
- Focus defaults to selected record profile; peers defaults to library default profile. Apply on clones with individual age/sex/context. Switching profile must not change raw-metric record sources.
- Snapshot reports. Reopen without silent recomputation. Update references explicitly; keep narrative and mark its basis stale after changed evidence. PDF defaults all saved references, optional current; chunk participants with repeated headers. HTML/JSON embed participant records and cohort contribution snapshots, remain consistent offline; reference imports are not active athlete imports.
- Independent report and snapshot storage, batch source reads under one database revision, shared computation across reference groups. Complete backups include new entities and accept old backups. Three report kinds use a shared ownership dispatch for narrative/views/AI/export and save barriers.
- User-facing UI should be practical and concise; configuration detail/source audit stays in expanders, not defensive paragraphs.

## Shared implementation interfaces (owners coordinate deviations before use)

- `RingsideMetricSemantics`: normalize/resolve definition statistics meaning and canonical direction, source/conflict flags; no source record mutation. Model owner exports the precise functions.
- `RingsideComparison`: shared observation extraction/comparability primitives used by longitudinal and horizontal, with legacy longitudinal output stable.
- `RingsideHorizontal.build(records, { participants, references, window, perspective, focusAthleteId, mode, profile, catalog, athletes, groups, classifications, views })`: synchronous pure build from complete candidate records; participants are `{athleteId,recordId}`; references are stable-id definitions with explicit resolved demographic conditions. Return serializable model with participants, references and per-reference sections/rows plus fingerprint. `facts(model)` is AI evidence. Model owner publishes exact model structure immediately.
- `RingsideHorizontal.buildAsync(records, options, {isCancelled, onProgress, batchSize, yieldControl})` uses the same generator as the synchronous build, yields between record batches and shares prepared records across reference groups. The report controller supports cancellation before persistence.
- `RingsideClassifications`: normalization/migration/resolve/merge for `{sports, subdivisions, ageBands}`. Root integrates management dialogs; profile form owner adds IDs with a dictionary option while retaining compatibility text.
- `RingsideHorizontalStore`: normalized document with stable `id`, revision, configuration, snapshot/model, narrative/previousNarrative, views. Repository separate get/list/save/delete report methods with optimistic revision checks; backups stream report metadata and snapshot chunks. Store owner publishes method signatures immediately.
- `RingsideHorizontalView.render(model,{views})` returns `{summary,body,screenItems,screenPill,overview,referenceLabel,legend,details}`. `mount(container,model,{onChange})` handles independent view changes. Controller owner provides setup/edit participant and reference UI, creation/reopen/refresh, view/narrative state, payload/export, and host contract.
- Root integrates a report-owner dispatcher in App, shell entrypoints, classification and metric editor controls, PDF, AI, build, test orchestration, versions/release.
